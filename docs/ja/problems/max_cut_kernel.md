# MaxCutKernel

**API:** [`MaxCutKernel`](../../api/optopus/problem/max_cut/struct.MaxCutKernel.html)

[MaxCut](max_cut.md) の厳密なデータ縮約 (kernelization) です。Ferizovic, Hespe, Lamm, Mnich, Schulz, Strash による
*Engineering Kernelization for Maximum Cut* ([arXiv:1905.10902](https://arxiv.org/abs/1905.10902)) に基づいています。

`MaxCutKernel::new` は最適値を保つ規則でインスタンスを縮めます。結果として、証明つきでより小さいインスタンス、定数のオフセット、
削除したすべての頂点を再導出するためのトレースが残ります。

## 例 { #example }

`MaxCutKernel` は [`ProblemReduction`](../traits.md#problemreduction) を実装しているので、
ヒューリスティクスは縮約をまたぐ役目を持つ `SearchState` の二つのメソッドを通してカーネルに到達します。

```rust
let kernel = MaxCutKernel::new(&mc);          // 規則はサイクルごとではなく一度だけ走らせる
let mut state = SearchState::new_with_seed(&mc, seed);

while !outer.is_done(&state) {
    let before = state.iteration;

    let mut sub = state.open_reduction(&kernel);   // ウォームスタートを射影し、シードは親の RNG から
    inner.run(&mut sub)?;
    state.close_reduction(&kernel, &sub);          // カウンタをマージし、持ち上げた解を取り込み、最良解を更新する

    if state.iteration == before {
        state.progress_iteration();                // 下の「予算」を参照
    }
}
```

## 規則 { #the-rules }

| 規則 | 前提条件 | 操作 | オフセット | 持ち上げ |
|---|---|---|---|---|
| Isolated | `deg(v) = 0` | `v` を削除 | `0` | 任意 |
| Pendant | `deg(v) = 1`、重み `w` | `v` を削除 | `max(0, w)` | `w > 0` のときに限り `a` の反対側 |
| Path | `deg(v) = 2`、隣接頂点 `a ≠ b`、重み `w₁, w₂` | `v` を削除し、辺 `(a,b)` に `Δ` を加える | `max(0, w₁+w₂)` | 得になる側 |
| Domination | `\|w(v,a)\| ≥ Σ_{u≠a} \|w(v,u)\|` | `v` を `a` に併合 | 下を参照 | `x[v] = x[a] XOR opposite` |

Path。`a` と `b` が同じ側にあるとき `v` が得られる最大は `max(0, w₁+w₂)` で、別々の側にあるときは
`max(w₁, w₂)` です。したがってこの組は、定数と、`(a,b)` がカットされるかどうかだけに依存する項とに分かれます。
後者は重み `Δ = max(w₁,w₂) − max(0, w₁+w₂)` の辺そのものです。重みがすべて 1 なら `Δ = −1`、オフセットは `+2` です。

Domination。接続する辺の一本がほかのすべての辺より重ければ、`v` をその辺が好む側に移すと、ほかの場所で失いうる分以上を得ます。
したがって、ちょうどそうしている最適解が存在します。`v` の側は `a` の側の関数になります。これは削除ではなく縮約です。
`v` のほかの辺はまだ決まっておらず、`a` に引き継がれるからです (`v` が `a` の反対側にあるときは符号を反転して引き継ぎます)。
これにより、Path 規則が作る重み付きグラフの上でも規則が連鎖し続けられます。

これらの規則は作業キューで不動点まで走ります。頂点は辺が変わったときだけ再検査されます。再びキューに入れる集合は、併合の後ではなく前に読まなければなりません。
辺を頂点 `a` に引き継ぐと、`a` の既存の辺の一本がちょうど 0 に打ち消されることがあり、その辺は両端から削除されます。
すると、次数が下がったばかりの頂点はもう `a` の近傍にはないので見つけられません。後から読んでいたときは、
削除できる頂点が残ったままのカーネルができていました (4〜14 頂点のランダムな符号付きインスタンス 40000 個のうち 127 個)。
これがさらに、辺を一本も持たない生き残りの頂点を生むことがありました。`Graph` は見えた最大の頂点 ID から大きさを決めるので、
カーネルのグラフが自分の頂点リストより短くなり、そのために作ったどの解も短すぎて持ち上げられませんでした。
現在は圧縮の段階で辺のない生き残りを孤立頂点として記録するので、`graph.len() == original_of.len()` は、
キューがすべてに到達したかどうかではなく構成によって成り立ちます。

## 縮むものと縮まないもの { #what-reduces-and-what-does-not }

縮約は次数の低いところで起きるので、これはチューニングではなくインスタンスの問題です。

| インスタンス | n | 平均次数 | カーネルの n | 削除率 |
|---|---|---|---|---|
| `ba_n10000_m001` (木) | 10000 | 2.0 | 0 | 100% |
| G70 | 8646 | 2.3 | 2164 | 75% |
| `er_n10000_d002` | 8589 | 2.3 | 2105 | 75% |
| `er_n20000_d003_pm10` | 19055 | 3.2 | 7780 | 59% |
| `ba_n10000_m002` | 10000 | 4.0 | 4955 | 50% |
| `er_n10000_d004` | 9807 | 4.1 | 7472 | 24% |
| `er_n05000_d005_w110` | 4969 | 5.1 | 3887 | 22% |
| G55 / G60 | 4969 / 6957 | 5.0 / 4.9 | 4351 / 6073 | 13% |
| G57 / G63 / G64 (正則) | 5000–7000 | 4–12 | 変化なし | 0% |
| G1、生成した密なインスタンス群 | 800–5000 | 48–1000 | 変化なし | 0% |

木ではカーネルは空になります。縮約だけで厳密な最適値 (すべての辺がカットされる) が得られます。

一方、4-正則グラフ (G57 / G63 / G64) や密なグラフ (G1) では、規則は一つも発火しません。
